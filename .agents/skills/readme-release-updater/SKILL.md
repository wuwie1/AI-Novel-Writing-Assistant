---

检查目标分支的 git status、diff、暂存区和提交历史，确认拟提交、推送或 PR 的完整范围。推送须比较远端跟踪分支到本地目标的全部未推送提交，合并重复条目。保留他人的改动。

判断改动是否影响用户能看到或操作的功能。纯内部改动跳过两个发布说明文件，并在交付中说明原因。用户可感知的改动按新增、优化、修复归类，略去空类，用用户视角说明具体能力、工作流和结果，避开内部文件、测试和实现细节。

docs/releases/release-notes.md 是完整历史。使用仓库日期标题（如 ### 2026-04-07），同一日期的更新合并为一段，保留以往日期。除非用户明确要求，不切换到语义版本。README.md 的“## 最新更新”只保留最新日期的合并摘要和完整历史链接，不积累旧日期。合并上游时复核已随提交引入的条目，避免重复记载。

在 Git 写操作前检查两处更新是否一致，并按仓库要求以新增：、优化：或修复：开头撰写新的提交标题。
