# 运行记录与 AI 创作实况的产品边界

## Background

新手在写作页面等待长篇生成时，需要立即知道 AI 是否仍在工作、正在生成什么、是否进入检查或修复。要求用户跳到“任务中心”才能确认进度，会打断当前创作上下文，也会把正常等待误解为后台故障。

## Decision

实时过程属于创作主界面能力：所有页面顶部提供“AI 实况”入口，打开同一份全局生成面板。原任务中心在产品中改称“运行记录”，只承担历史追溯、异常查询、恢复位置说明和来源页面定位。继续、恢复、重试等操作必须留在能够展示创作上下文与影响范围的来源页面。

## Current Rule

1. 正常生成、规划、正文写作和修复过程中，用户不需要进入运行记录；顶部“AI 实况”应直接显示返回片段与生成阶段。
2. “AI 实况”的日志展示临时返回片段。在小说创作页打开实况，可以按书名暂停自动导演或从保存进度继续。操作目标取自该页小说的服务端任务投影，全局日志中其他书的新调用不会切换目标。在运行记录等非创作页面打开实况时，通过小说链接返回工作台操作。
3. 运行记录保留统一任务的来源、步骤、状态、异常、恢复位置和历史信息，供用户在确有问题或需要追溯时按需查询。
4. 运行记录不得提供继续、恢复、重试、取消、重规划、修复、审批、归档或其他会改写任务状态的操作。允许的交互只有刷新、筛选、选择记录、展开诊断信息和打开来源页面。
5. 自动导演与章节质量债的主入口仍属于小说工作台和导演跟进；运行记录只提供事实查询与来源跳转，不重新裁决创作主状态。
6. 运行记录默认采用任务收件箱心智：先展示需要处理、等待操作和正在推进的记录，再展示错误、恢复位置与来源入口。模型、Token、心跳、完整时间、检查点和细分步骤属于诊断信息，应在选中记录后按需展开，不能长期铺在列表中迫使新手读取内部运行字段。
7. 任务投影、失败记录和恢复候选必须提供稳定的 `sourceRoute`。来源页面负责根据完整上下文展示可执行动作、动作影响和处理中状态。
8. 新手引导、普通按钮和页面文案应优先让用户留在当前创作现场。运行记录可以帮助确认事实，但不能被描述成恢复或重试入口。
9. 从书架删除小说时，本书各状态的工作流、Agent、流水线、图片和新旧导演运行均随书清理。删除事务完成后，书架同时刷新运行记录、导演历史、恢复候选和跟进列表。新书创建前产生的无归属任务以及公共知识文档有各自的生命周期。

### 删除与正在执行的任务

删书事务先锁定小说，撤销可供后台领取的任务和租约，清理时间线、按来源索引的作业和本书的知识分块。运行历史、执行器和模型调用共享同一项运行的取消信号。事务提交后通知同进程执行者，分离运行的导演 Worker 在续租失败时停止。事务回滚时，当前创作可以继续。

向量库、对象存储和本地图片目录不能参加数据库事务。发布封面或本书向量前先登记存储位置，在提交业务记录时一并解除登记。删书事务把正在写入和已发布的资源登记为独立清理任务。向量清理按写入时的集合和分块 ID 定位，缺少集合信息的旧分块使用删除时配置的集合。封面清理只使用本书和图片任务名下的托管位置。外部存储失败可重试，知识检索只接受仍有本地索引记录的命中。

## 来源页面的记录删除与停止边界

已结束记录的移除也会改变历史可见性，属于写操作。即使后端只保存归档标记，也不能放在只读的运行记录页面。导演推进、拆书分析等来源页面可逐条确认移除已结束记录：复用 `TaskCenterArchive` 保存移除标记，保留任务和创作成果的完整关联，不执行实体物理删除。确认对话框必须说明小说、章节、分析内容和来源资料会保留。停止入口同样属于导演推进、拆书或图片生成等来源页面。

- `DELETE /api/tasks/:kind/:id` 只接受已完成、失败或已取消任务；拆书草稿与已归档分析也可移除。运行中、排队中和等待审批返回 409，提示先停止。
- 拆书列表与统一运行记录读取相同移除标记；导演推进读取已有工作流归档标记。列表删除不得清除任何已发布结果、小说引用或分析小节。
- 停止沿用各业务取消状态机。拆书同进程取消立即中断请求，另一个进程的持久化取消标记通过短周期检查到达执行中的 AbortSignal；源文笔记、分析小节以及必要的章节识别调用均要携带取消信号。
- 图片任务同样读取持久化取消标记并中断供应商请求，取消不能触发自动重试。供应商已收到请求后，其远端计费或任务是否立即终止由供应商决定；本地必须停止等待和后续调用。
- 手机端保留停止入口，列表删除默认隐藏。删除失败应保留确认框并显示错误，成功后重新读取相关列表。

诊断停止问题时，同时核对持久化状态、供应商请求的 abort、停止后的请求次数，以及 watchdog 是否错误恢复已取消任务；只看到按钮文字变化不足以证明停止有效。

## Failure Modes

- 用运行记录的轮询状态替代当前页面的创作反馈：用户会离开当前创作步骤并误以为普通生成需要人工处理。
- 把实况预览当作已保存正文：必须继续显示检查与保存阶段，且最终结果仍以原业务页面的资产状态为准。
- 为了简化入口而隐藏失败与恢复信息：运行记录仍需可达，并保留稳定的来源与恢复路径。
- 在运行记录详情中放置重试、恢复、取消或归档按钮：用户看不到完整创作上下文，容易误判影响范围，也会让来源页面与运行记录形成两套操作事实。
- 文案要求用户“去任务中心恢复”：应改为先查看运行记录确认事实，再回到来源页面执行恢复。
- 小说删除后仍出现无来源失败记录：检查书架删除是否撤销本书任务和归档标记，并覆盖导演运行历史以及 Worker 候选查询；不要用运行记录页面的批量删除按钮掩盖生命周期缺口。
- 导演 V2 任务可能在删书后仍显示「运行中」。`DirectorNextRun.novelId` 没有指向 `Novel` 的外键。按任务 ID 能读到历史记录，而书籍入口和暂停命令会因归属小说缺失返回 404。维护时先确认非空书籍 ID 确实没有对应小说，并检查执行租约。获准清理并验证备份后，按核实的运行 ID 限定事务范围。运行的产物索引在删除运行时会解除关联，需先核对其 `producedByRunId` 与 `novelId`。模型用量账本和独立创作资料应保留。
