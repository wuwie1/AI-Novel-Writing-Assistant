# 漫画项目删除与资产归属

## 背景与决策

漫画项目拥有导入快照、角色、场景、话数、分格、事实、图片和导出记录。数据库级联删除不会清理文件系统，因此项目删除必须经由 `services/comic/lifecycle`，不能直接删除项目行。来源小说通过软引用关联，删除漫画不得追溯删除原小说。

## 当前规则

- 删除入口位于漫画项目列表，确认框说明影响范围。确认后才请求删除；失败保留确认框和错误原因，成功刷新漫画列表。
- 项目记录连同全部子记录写入 `storage/comic-project-backups/<随机标识>/project.json`。图片、角色设计稿历史版本、表情与派生参考图、场景图、带字分格和导出文件复制到同目录的 `files/`，按文件 SHA-256 校验。备份路径写入服务日志，`manifest.json` 记录项目和文件目录。
- 备份未完成或校验失败，不能清理原文件或数据库。文件清理、数据库删除失败时从备份恢复文件；保留备份以便管理员排障。备份不属于在线项目资产，不随删除清理，工作台不提供自动恢复入口。
- 仅根据数据库中的所属实体 ID 构造漫画专用目录；不信任图片 URL、导出描述或任意上传路径。未知归属的上传文件、异常标识和符号链接须拒绝处理，不能扩大删除范围。
- 角色、角色资产、场景、话数、分格、事实、导入快照、上传记录和批量/导出任务由外键级联删除。两种 Prisma schema 的归属关系必须保持一致。
- 运行中的批量、导出或图片生成阻止删除。待执行任务同样阻止删除，避免后台工作继续写入已删除项目。

## 并发边界与故障处理

当前漫画 API 在单进程运行。HTTP 写操作经 `comicMutationHandler` 进入进程内计数，只有所有写操作完成后才能开始删除；删除期间拒绝新的漫画写操作。计数随处理函数实际结束释放，不以浏览器断开连接为准。异步批量生成由已落库的任务状态补充保护。普通读取保持可用；会写入派生图片的读取入口也必须纳入保护。

此保护短时覆盖整个漫画模块，不影响小说写作。若漫画服务扩展为多进程或独立 worker，必须先改为数据库租约/项目生命周期锁，禁止直接复用进程内互斥假定。新增脱离 HTTP 的异步任务必须先落库，并在其全部写入结束后才改成终态。

文件系统和数据库无法组成同一事务。若进程在清理期间崩溃，管理员先核对项目行是否存在与日志中的备份目录；项目仍存在时可从 `files/` 按原相对路径恢复文件，项目已删除时保留备份用于人工恢复。不得用清空数据库解决中断。异常退出遗留的生成状态须核实任务已停止后处理，不应为了允许删除而自动清除状态。
