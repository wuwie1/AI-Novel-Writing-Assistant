# 参考创作的证据覆盖与费用核对

## 背景

原文导入、拆书、写法提取、知识检索和热门题材分析会把不同深度的材料交给后续创作。新手容易把“导入成功”理解为全文已分析，把“分析成功”理解为正文生成能够检索全文，把界面的 token 累计理解为完整账单。

这些状态分别属于文档、分析、索引和真实模型请求。解释参考效果或估算费用时，必须先明确实际来源和调用范围，避免用任务名称替代证据。

## 当前核对规则

### 来源版本与覆盖范围

- 磁盘文件、知识库版本、章节阅读器缓存和拆书输入范围应分别核对。标题相同、字节数相近不能证明版本相同；优先比较内容哈希，必要时补充标准化长度与去空白哈希。
- `DocumentChapter` 的目录缓存与 `buildSourceSegments` 的笔记分段不是同一个产物。阅读器能列出章节，不证明笔记阶段逐章调用了模型。
- 基础拆书能识别至少三个有效章节段时，按顺序将章节合并为最多十二个大段；合并结果没有再次受 `MAX_SEGMENT_CHARS` 限制。不能用“片段数乘一万字符”估算该路径的输入。
- 无法可靠识别章节时，基础笔记分段按字符切片后只保留前十二片。这个路径可能没有覆盖长文本后半部，不能把报告称为已经逐段核对全文。
- “快速、标准、完整”主要选择报告维度。减少小节数量并不自动缩小 source notes 读取的原文范围。降低首次拆书成本应先比较原文范围与可复用缓存。

### 实际调用与任务累计

- 费用依据应优先使用物理调用账本中的输入、输出、缓存命中与有效模型，并核对失败请求、格式修复、业务重试和额外研究动作。调用 `completed` 不等于其结果被业务接受。
- 当前基础拆书编排在小节完成后调用 `BookAnalysisBudgetGuard`；source notes 生成没有向同一个守卫结算用量。因此未经逐阶段核对，不得把 `BookAnalysis.usedTokens` 或 `budgetTokens` 宣称为整次分析的完整用量或严格付费上限。
- 调用后才判断预算与并发在途调用也会产生超额窗口。严格额度需要在真实请求前预约，返回后按 usage 结算；失败与远端结果未知的状态不能简单清零。
- 账本缺少分析任务关联标识时，只能依据来源数量、时间窗、模型和调用用途建立有限归属，必须说明证据强度。多个任务并发时不能按时间窗直接强行分账。
- 金额按请求的模型、计费时段及缓存字段回算，不等同于供应商账单。估算、实测 token 和实际扣费必须分别标记。

### 缓存与有效模型

- source notes 本地缓存身份包含文档版本、范围、厂商、模型、温度、笔记输出额度和分段版本。不同来源范围不能共享全文缓存；切换模型也不能假定复用旧模型笔记。
- 本地笔记缓存命中会跳过相应生成调用；供应商输入缓存只改变该次请求的计费，两者不能混为一谈。
- 当前顶部模型、任务路由、厂商默认模型和已保存任务模型是不同事实源。显式 provider/model 会影响路由覆盖，恢复应尊重任务快照；费用说明必须展示真正调用的模型。
- 全局账本与任务累计的计量覆盖应随实现维护。补齐计量后，应同时调整本页对当前缺口的描述，不能长期保留失效结论。

## 参考材料的能力边界

- “照着一本书写”的主参考入口为单选，承接方案绑定单一拆书。多文档知识绑定只提供辅助资料能力，不代表存在完整的多书权重融合合同。
- 部分传统大纲、设定与节拍服务会汇集多份绑定分析，但合并参考文本受到总字符上限限制。检查是否真正消费多本材料，应看实际上下文与裁剪结果，不能只看数据库中绑定了多少份文档。
- 参考创作承接方案要求剧情结构、文风技法和商业化卖点；续写承接要求人物系统与剧情结构，并要求原文版本可读。快速拆书缺少商业化卖点，不能无条件承诺“一次快速拆书直接参考开书”。
- 写法资产通常读取拆书的文风小节，经过再次压缩形成规则。它不能替代原文证据、人物终局事实或新书自己的世界约束。
- 发布拆书、绑定知识和正文检索也应分别验证。拆书直接读取文档版本，索引失败不必然阻止拆书；后续需要 RAG 的动作却可能无法召回这些材料。

## 热门题材的证据边界

- 雷达读取公开榜单元数据，不是自动下载并分析上榜作品正文。
- 当前番茄采集可带简介，简介进入平台分析前会截短；起点、晋江当前解析字段更少。番茄混淆文本的详情补抓仍是恢复元数据，不是章节正文分析。
- 作品多选与信号多选是两个动作。作品按平台汇总分析；创作简报接受一至五项信号。不能把选择多本作品解释为多次整书分析。
- 热度与拥挤度是 AI 基于所给证据的判断，不是销量、留存、付费转化或成功概率。没有可比较历史快照时不能声称证实了上升趋势。

## 建议的费用验证路径

1. 固定代码基线、数据源和源版本，只读读取有效模型与任务配置，避免展示密钥。
2. 复现实际原文范围与分段构造，区分字符数、token 数、输入与输出。
3. 按笔记、小节、写法、承接、规划、草稿、验收、修复、回填和索引分类核对调用；索引按 embedding 或重排单价单列。
4. 先完成三至五章试写，再用每章调用结构、修复比例与有效模型估算剩余范围。小样本不能证明整书生成已经稳定。
5. 核对已保存正文、状态回填、质量债与下一步来源页；运行记录只展示与导航，不承担恢复或重试操作。
