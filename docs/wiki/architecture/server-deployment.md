# 私有服务器部署与本地访问边界

## 背景与决策

源码 Web 服务包含会修改创作内容、模型设置和任务状态的接口。个人服务器将 API 和网页绑定到回环地址，通过 SSH 本地转发访问。部署者可另外配置 `AI_NOVEL_ACCESS_TOKEN`，为业务 API 启用应用层认证。未配置令牌时，访问控制仍依赖回环监听和 SSH。[访问令牌边界](./access-token-boundary.md)

## 当前规则

- `infra/server/` 拥有部署进程控制、Nginx 代理和本地 autossh 通道。根目录 start/restart/stop 仅委托给此模块，不包含业务恢复、数据库初始化或迁移。
- systemd 管理 API 和静态网页进程，专用账户拥有数据库、资产和日志目录的写权限。停止指令只停止此部署的服务，不按端口批量杀进程，不干预同机其他应用。
- 网页与 API 通过同一入口访问，`/api` 原路径转发，禁止缓冲 AI 流式输出。本地映射只绑定 `127.0.0.1`，沿用 SSH 主机校验并用 autossh 保持连接。
- `make ssh_server` 与桌面启停共用生命周期锁。独立 Web 隧道必须能追溯到本仓库的 autossh，SSH 子进程的目标及转发端口必须匹配，网页和 API 健康检查也须通过。仓库改名后，旧管理进程仍可能存活并反复重连。它打开的日志文件随目录移动，可用于确认归属，从当前路径恢复通道。
- 先启动独立通道时，桌面借用它。若桌面先建了自有通道，浏览器使用单独的回环端口并记住地址，避免打断窗口中正在保存或生成的请求。退出桌面只释放桌面自有通道。遇到归属不明的端口应提示选择空闲端口。
- `make ssh_server` 同时管理 Qdrant 的回环转发。Web 和 Qdrant 分别记录 autossh 的 PID 与日志，补建知识库通道时可保留进行中的 Web 请求。管理页从本机经 SSH 访问，应用索引从 API 主机直接访问向量库。两项服务分别探测，Qdrant 的就绪状态只影响管理页提示。
- 服务监督恢复的是进程，不是创作授权。任务的人工暂停、质量优先暂停、重试与恢复仍由原有运行时合同决定；启停脚本不能修改任务表或调用恢复 API。
- 静止检查必须按业务表解释交接终态。`CreationStudioConfirmation.handed_off` 表示创作方向已交给长篇导演，这条确认记录自身没有待执行工作；后续是否正在生成仍由 `NovelWorkflowTask`、导演控制、生产请求和租约等表独立判断。该状态只对确认表有效，不能加入全局终态白名单。`claimed`、未知状态和仍活跃的后续任务继续阻止停服；不得通过修改历史确认记录来让部署通过。
- Web 模式不能依赖桌面运行时迁移。首次空库由正式迁移初始化；已有库迁移先做可验证的一致备份，涉及数据删除时取得明确批准。
- 部署验收分别读取网页、公开健康接口和小说列表。小说列表必须实际读取成功。启用令牌时，探针从服务器的 `server/.env` 读取凭据，仅将其发送给回环地址的小说列表请求，重定向不携带凭据。
- 运行日志与应用细粒度日志分开：`logs` 保存固定进程/访问日志，由系统轮转；`.logs` 保留应用诊断。源码更新不能覆盖数据、资产、密钥和日志。

## 实况订阅与部署排空

`/api/llm-live/stream` 是只读观察流，15 秒心跳会使它长期保持连接。Nginx reload 只阻止新请求，旧 worker 仍服务已有流，因此仅等待 TCP 连接消失会让没有生成任务的部署也超时。不要用强杀所有 Nginx worker、忽略所有连接或修改任务状态来解决。

- 部署先检查持久任务空闲、开启 Nginx 维护入口，再原子写入 `server/storage/.llm-live-drain.json`。协议为 `version=1`、随机 `owner`、毫秒时间戳 `expiresAt`，有效期 90 秒。文件权限为 0644，供专用 API 账户读取；不含凭据或创作内容。
- 仅实况观察入口读取此标记。已建立的订阅每秒检查并结束响应，释放心跳、轮询和 broker 监听器；新订阅返回 503 和重试提示。观察流使用 `Connection: close`，结束响应时同时释放上游 TCP 连接。
- 结束观察不结束模型调用、不取消任务、不清空 broker 会话。客户端沿用自动重连，并用最新快照补齐断线期间的内容。实际正文/模型生成流不读取这个标记，仍阻止连接排空；持久任务检查和两次连接空闲采样也不变。
- 服务停止后、最终备份之前清除标记；排空超时或部署回滚时同样按 owner 清理，再恢复入口。进程异常退出留下的标记到期后失效，不能永久阻止实况订阅。手工遗留的未知标记不得作为清理业务数据的理由。
- 首次升级到支持此协议的版本时，旧 API 无法识别标记。只允许在核实持久任务和实时模型均空闲、连接全部归属本部署后进行一次受控停服，再部署。新版上线后应保留一个实况连接执行同版本部署，验证排空流程自动通过。

影响范围：私有服务器部署流程与 LLM 实况只读投影。自动导演授权、章节生成、任务恢复及数据库内容不受此标记控制。

## Fork 与部署目录的版本管理

- 二次开发使用维护者的 fork 作为 `origin`，原项目作为 `upstream`。上游远端 HEAD 标识原项目的默认发布线，当前工作区的分支标识本轮接收更新的目标，两者可以异名。检查和同步只比较这个目标与上游，以及 fork 的同名分支。新本地分支尚无 fork 引用时仍可检查和本地同步。
- 合并须保留当前分支原有提交和用户文件。存在未提交修改时，在独立 worktree 整合，再将验证过的结果安全快进到原分支。若覆盖保护阻止快进，保留隔离结果供继续处理。推送仅更新 fork 的同名分支，部署使用同一候选且核对服务器实际发布分支，防止一个工作区的操作推进其他发布线。
- 上游同步、差距检查脚本和发布说明技能在仓库的 `.agents/skills/` 一起维护。Git 远端和部署凭据在各开发机配置。[项目维护技能](../../../skill_tools.md)
- “服务器更新”和 `make server_update` 使用同一条部署流程。开发机固定当前干净发布分支的 HEAD，按需通过 SSH 传输增量 Git bundle，服务器访问 GitHub 的网络状况不会影响代码传输。服务器在部署锁内复核基线、校验候选 SHA 和前置提交，先导入 Git 对象，完成备份后再快进工作树并替换产物。即便提交相同，也要重启并验收 API 和网页服务。[部署事务与回滚](mac-desktop.md#部署与回滚)
- 切换前记录工作区状态、各分支提交和服务器部署提交，并保存 Git 配置及可验证的 Git bundle。bundle 保护提交历史，不包含数据库、环境配置、运行日志或未提交文件，不能替代运行数据备份。
- 通过源码包部署而没有 `.git` 的目录，可先导入与当前部署匹配的提交，再设置分支和索引。初始化时只写 Git 元数据，不使用强制 checkout、hard reset 或 clean 覆盖现有文件；随后检查工作区差异，把服务器本地修改保留为可审查差异。
- `.env`、`data/`、`server/storage/`、`.runtime/` 和日志继续保持忽略。仅切换仓库来源或导入版本元数据不需要构建、迁移或重启应用。
- 部署清单同时记录代码提交、分支及来源仓库。网络或认证问题不能通过复制开发机私钥到服务器、关闭主机校验或覆盖运行数据来解决。

## 常见失败

1. 仅构建 shared 但未同步注入的工作区依赖，会使服务找不到运行时模块。构建后用离线冻结安装同步 shared 输出。
2. 仅创建 SQLite 文件而未执行 Web 迁移，健康检查可能无法代表完整业务就绪。部署验收同时检查数据库读取接口。
3. 后台进程能启动但专用账户无数据库目录写权限，会导致 SQLite WAL 或资产写入失败。数据文件与其目录都必须归运行账户所有。
4. 不应把系统日志放入应用自动清理的目录，否则长期未更新的固定日志可能被当作历史文件删除。
5. 若生产 API 启动时报 `DATABASE_URL is required in production.`，以服务账户在 `server/` 目录运行 `../.runtime/node/bin/node --require dotenv/config -p 'Boolean(process.env.DATABASE_URL)'`。返回 `true` 说明服务账户能读取配置，应检查入口是否在加载 `dotenv/config` 前间接导入了 Prisma。systemd 可在 API 的 Node 启动命令中将 `--require dotenv/config` 放在脚本路径前，使配置在业务模块加载前生效。
6. 构建时 SSH 和 API 同时超时、日志最后停在 `tsc`，应先检查内核 OOM 日志和可用内存。约 4 GB 主机即使有交换空间，3 GiB 的编译堆加上在线服务仍可能耗尽内存，连带终止 API；构建尚未进入切换事务并不代表在线服务不受资源竞争影响。不要原样反复重试。可在开发机完成完整检查，向 `DEPLOY_VALIDATION_FILE` 提供绑定候选 SHA 的真实证据：远端只对后端执行 `--noCheck` 产物生成，保留 Linux 依赖、Prisma 生成、前端构建及隔离数据库的冒烟测试。外部检查不能替代目标主机运行验证；任何生成或冒烟失败仍须在备份和切换前终止。复用旧检查时必须证明全部相关输入和工具链未变，记录来源提交和日志，禁止仅替换记录中的 SHA。
