# 本机模型代理与服务器任务边界

## 背景与决策

部分部署需要通过用户电脑的网络访问 OpenAI 兼容模型服务。自动导演、章节生产、结构化校验和保存均属于服务端任务链。为保持任务语义一致，网络出口通过本机 HTTP 代理和 SSH 反向通道改变，业务编排继续留在服务端。

浏览器只保存厂商连接地址，不承担模型请求执行，因此关闭浏览器不影响已启动的代理。电脑休眠、断网或停止代理仍会中断模型通信，不能承诺脱离本机继续生成。

## 当前规则

- `proxy/` 只在本机运行。上游以忽略的 `proxy/config.toml` 中 `openai.url` 为准，模板提交到仓库；所有启用代理的厂商共享一个 OpenAI 兼容上游，不按名称猜测协议或路由。
- 服务器 `127.0.0.1:14000` 经反向 SSH 转到本机相同端口。只接受回环监听；服务端 `GatewayPorts=yes` 可能覆盖客户端绑定，因此健康检查同时核对监听地址和实例身份。
- “添加厂商”弹窗提供与“自定义厂商”并列的“添加本机模型”入口。普通厂商连接表单不提供代理开关，避免用户将已有厂商的模型、密钥误用到本机代理配置的另一个上游。
- 本机模型复用自定义厂商的持久化和模型目录接口，创建时自动命名并固定 `baseURL` 为 `http://127.0.0.1:14000/v1`。名称可修改，隧道地址不可修改；获取模型列表、连接测试和保存均读取同一地址。重新编辑时根据自定义厂商的已保存地址识别本机连接，卡片展示“本机模型”。不另存可能与地址矛盾的布尔值，不增加数据库迁移。
- 普通自定义厂商仍手动填写 API 地址，空地址不能提交。历史内置厂商即使保存了代理地址，也保留原配置并允许编辑 API 地址，不自动迁移、复制或改写连接；固定端点的自定义连接按本机模型展示。
- 模型列表、连接测试、正式文本及图片生成沿用相同厂商地址和鉴权。知识库只有使用该厂商地址的请求随之转发；另行配置的重排地址等不会自动改写。余额等非 OpenAI 标准接口不属于该代理承诺。
- 转发仅调整 API 前缀，不积累请求/响应，不记录模型内容或密钥，不重试、不修复 JSON、不转换协议。失败、用量和结构化结果仍由原有服务端调用链处理。
- `make ssh_server` 启动或复用 Web、Qdrant、本机代理和反向通道；restart/stop 命令只控制本机持有的独立进程，不重启远端应用，不修改任务状态，也不解除人工暂停。
- 所有生命周期命令复用仓库锁，只管理完整参数匹配的进程。启动健康检查确认同一实例，失败仅回收本次新建进程。归属不明的监听和进程不能被当作可复用代理或被终止。
- 隧道用 autossh 重连；代理进程意外退出需要重新启动。离线错误交给既有任务失败/恢复规则，不自动改成直连，不因网络恢复而自动授权任务继续。

## 部署范围

代理及本机隧道不是服务器构建输入，不进入后端运行依赖；Git 源码同步可能带上脚本，但不会在服务器启动代理，也不会同步本机配置。页面入口属于前端产物，需发布服务器托管的网页。部署计划必须分别识别这些输入，不能把修改本机代理误判为后端需要重建。

## 失败诊断

1. 先运行 `bash infra/server/tunnel.sh status`，区分本机代理、反向隧道与网页访问通道。
2. 本机 `/health` 不通时，检查 Python/TOML 配置与 14000 端口；启动失败不输出配置原文。
3. 本机正常但服务端不可达时，检查 SSH 转发授权、远端端口冲突及回环监听策略；无需开放公网 14000 端口。
4. 健康接口正常但模型报错时，核对实际上游的模型名、API Key 和协议。健康检查只证明代理路径，不证明厂商凭据或模型可用。
5. 配置修改后运行重启命令；普通启动检测到配置变化时要求明确重启，避免界面连接到旧上游。
