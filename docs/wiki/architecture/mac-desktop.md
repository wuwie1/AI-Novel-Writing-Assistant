# Mac 桌面运行与呈现边界

## 背景与决定

Mac 用户需要 wukong 风格的原生工作台，同时继续使用现有小说生产服务。因此 Mac 采用独立 Swift/AppKit/WKWebView 与 React renderer；它既不是远程 Web 首页的快捷窗口，也不携带另一套小说业务后端。共享客户端能力通过显式可选入口复用，避免两端逐步出现不同的任务恢复或 AI 决策。

## 模块所有权

- `desktop_mac/native`：窗口、菜单、原生文件交互、单实例 socket、最小消息桥。只允许本机受控 origin；外部网页交给系统浏览器。
- `desktop_mac/renderer`：Mac 外壳、页面呈现、主题和平台适配。所有外观规则限制在 `html[data-app-shell="mac"]`，不导入 Web 全局 CSS。
- `client/src/router/createAppRoutes`：路径和功能开关的单一来源，允许注入 layout/pageOverrides；默认 Web 路由不变。
- `client/src/platform`：可选的文档状态、草稿存储和正文默认排版合同。状态由业务编辑器注册；不得扫描按钮文本或 DOM 来判断保存是否完成。
- `desktop_mac/application/lifecycle`：请求模式、成功模式、构建与进程切换。OS操作通过基础设施适配器；`.runtime/desktop_mac/state.json` 是原子写入的归属记录。
- `desktop_mac/application/deployment`：发布检查、构建、备份和停机事务；不执行迁移或业务命令。

## 连接与输入保护

Mac 界面只请求同源 `/api`。本机代理先验证回环 Host/Origin，再流式转发到固定本机API或SSH通道；不重放写请求、不汇聚SSE响应、不记录正文。远端API没有独立认证边界，因此必须保持服务器回环监听及SSH访问，不能为了桌面连接改为公网监听。

本地与服务器模式，以及不同后端身份，使用不同 WKWebView 数据存储与草稿前缀。主题也使用 Mac 专属键。正文草稿继续使用现有保存基线/版本冲突合同；服务器版本变动不能直接覆盖未保存输入。

原生桥协议版本 1 使用 `rendererReady`、`requestSave`、`requestClose` 和 `closeDecision`。`closeNeedsAttention` 让原生窗口展示当前退出请求需要的交互，`closeExpired` 让页面撤回同一请求。退出或重载必须等 renderer 允许。保存失败、忙碌、取消或超时时保留窗口。Mac 使用 `createBrowserRouter` 提供导航 blocker 所需的 data-router 上下文。

跨端同步依赖原生激活信号：WKWebView 在切换到其他应用再切回时不会触发 `visibilitychange`，而 Mac 的 QueryClient 全局关闭了 `refetchOnWindowFocus`。因此 `windowDidBecomeKey` 向页面发送 `windowActivated` 事件，`MacDocumentProtection` 收到后只重取当前挂载且已过期的查询；存在已登记的未保存或忙碌文档时跳过，避免另一端的改动覆盖本机输入。不要为了同步改成全局轮询或无条件 `invalidateQueries`。

红色关闭按钮仅隐藏现有窗口和 WebView；Dock 重开不重载。窗口位置、上次路由和持久草稿按后端身份隔离。WebContent 异常由用户选择重新打开，不能无提示重载。

普通窗口在屏幕变化或唤醒时按 `NSScreen.visibleFrame` 校正位置和大小。这个区域可能扣除 Dock 和菜单栏，套用到全屏窗口会在桌面空间边缘留下空隙。全屏和进出全屏的动画期间由 AppKit 管理窗口尺寸，过渡结束或失败后再按实际窗口状态处理。窗口重新可见时沿用现有 WebView 完成布局和重绘，以保留编辑位置和未保存输入。

文档保护覆盖范围以 `desktop_mac/docs/route-parity.md` 为准。新增状态编辑器需注册明确的 dirty/busy/save/discard 能力；不要把只修改了外观的页面误认为已具备退出保护。

离开提醒只读取状态所有者注册的真实 dirty/busy。不得为整个可编辑路由登记永久的“请确认已保存”：这会让未编辑、已保存、仅浏览列表的用户每次导航都确认，并掩盖编辑器状态接入的缺口。保存成功且所有注册文档已干净后直接继续导航，不追加页面级确认；保存失败、取消或忙碌仍保留页面。尚未接入的表单沿用页内保存，并在覆盖表明确标记。

## 菜单与列表栏

参照 wukong 的 `web/src/app/AppShell.jsx`：当前 view 决定列表栏是否出现及由哪个功能拥有，已选小说只属于书内上下文。本项目用当前 React Router 路由派生 `MacNavigation`，不把上次小说 ID 作为全局侧栏回退。

| 当前页面 | 列表栏内容 |
| --- | --- |
| 新建 | 从想法开始、填写设定、AI 自动创作 |
| 书架 | 最近小说与全部作品入口 |
| 小说工作台 / 章节 / 小说导演台 | 当前作品、与 Web `?stage=` 对齐的 8 步写作步骤、章节目录；章节编辑、书内导演台默认折叠，可主动展开 |
| 创作中枢 | 创作对话列表；工作区已有会话目录，外层目录默认折叠 |
| 导演 / 导演跟进 | 相关入口与最近创作记录 |
| 运行记录 | 状态筛选，只读取及导航 |
| 短剧 / 漫画 | 对应项目列表 |
| 资料、素材、写作工具 | 同类功能入口；资源条目由对应业务页呈现 |
| 设置 / 帮助 | 设置分类 / 创作指南入口 |

`renderer/src/shell/navigation.ts` 负责导航呈现元数据，`shell/sidebar/` 负责相应列表读取，布局不持有跨菜单的小说选择。仅挂载当前功能的列表读取器；全局菜单不得加载旧小说章节。标题、图标选中、列表栏名称和展开按钮来自同一上下文。导航取消时仍显示原路由列表；成功切换后收起临时抽屉并重置列表滚动，折叠偏好按功能保留。

运行记录的状态使用 URL 参数作为单一来源，侧栏、页内筛选及前进后退保持同步；详情选择保留当前筛选，筛选变更不能携带旧筛选的分页游标。此入口仍没有任何任务变更动作。运行记录的 `currentStage` 与步骤标签经 `formatTaskStage` 转为中文阶段名，避免把 `project_setup` 一类内部键直接展示给用户。

书架筛选（搜索、状态、写作模式、叙事形态、排序、视图、分页）写入 URL 查询参数，⌘R 后可恢复；筛选为空时的空态必须区分「书架本来没有作品」和「当前筛选没有结果」。

工具栏展示当前模型选择器与版本角标；版本角标打开 Mac 专属更新说明，不依赖 Electron 的 `APP_RUNTIME=desktop`。导演与运行记录图标可显示待处理角标，仅作提示，不提供任务变更动作。

错误 Toast 默认约 12 秒并带关闭按钮，成功提示会先清掉旧错误，避免残留气泡挡住按钮。引导弹窗在用户主动关闭后写入本地“已关闭”标记，进入 AI 页面时不再带着旧错误反复弹出。

业务页通过 `EntityList` 注册集合标识、名称和已选键。Mac 将内容渲染进稳定的容器，Web 在原位置渲染。抽屉开关仅改变可见性与键盘可达性，避免重复挂载编辑器或请求控制器。无集合视图同时隐藏栏、开关及其焦点。

运行记录按 `(kind,id)` 独立读取详情，`filterKind/status/q` 与游标只属于列表。改变筛选清空游标，保留详情。空列表与详情 404 分别呈现，角标、轮询、刷新及选行只调用读接口。

书架由 `NovelList` 同时提供当前页数据和作品动作。`selectedNovelId` 可单独恢复摘要，页外作品使用带 `workspaceSourceRoute` 的详情；`layout` 优先于旧 `view`。搜索仅在其发起时的 URL 仍有效时提交。开书候选按任务、批次及实体定位，预览独立于确认。

书内列表取当前活动页的作品投影。章节预览与编辑可复用作品详情中的章节，卷分组只采用明确的正文章节关联。规划章使用 `plannedChapterId`，仅在能够匹配真实正文时提供编辑入口。短篇分段在同一份编辑草稿中切换，连续阅读占用整幅画布。

导演历史的查询键须包含读取条数及关注筛选，以隔离 20 条角标与 50 条历史。运行以版本和运行 ID 定位，跟进事项以真实导演任务 ID 定位。书内资源目录只消费当前作品和类型的投影，会话选择由创作中枢统一检查忙碌状态、更新资源绑定。

文档版本的阅读、成为激活版本、作为拆书来源是三个独立操作。参考拆书按文档与版本取材，拆书详情和作品诊断沿用各自的来源 ID。市场条目归属具体扫描或报告，查看条目和加入简报多选独立。进入参考开书只读取已有资料，AI 生成须由创作者发起。

素材树以节点 ID 与完整父路径定位，同名节点可以分别维护。世界资料区区分本世界快照、已绑定参考和可引用的共享素材。正文实验以来源书章锁定上下文，目录搜索仅过滤可见条目；更换提示词或作用域须通过当前文档保护。

改编的项目和分集 ID 均归属当前改编类型，漫画工作台由项目控制器统一读取分话，详情、格子与导出使用同一投影。设置分类属于画布导航，厂商与任务模型才是列表对象。任务路由和备用模型的保存失败须保留草稿及当前选择。旧对话以本地会话为所有者，切换时同步对应运行。

## 视觉基线与级联规则

参考目录是 `/Users/likai/go/src/write/wukong`。不能只抄 `base.css` 的通用变量：wukong 的入口按 `app.css` → `base.css` → `demo.css` → `studio.css` → `side-panels.css` 导入，最终效果同时受选择器优先级和功能页面覆盖影响。灵感列表的浅蓝选中条来自 `demo.css` 的 `material-list-item.is-selected`，不是图标栏的灰色 `--active`。以正在运行的窗口和完整级联共同核对。

- 外壳采用两行网格：40px 顶栏横跨中栏与画布；64px 图标轨道跨两行；244px 中栏与内容画布在第二行。标题/折叠按钮位于中栏上方。窄窗抽屉从顶栏下方展开。
- 图标栏 `#eeeeee`、中栏 `#f4f4f2`、画布 `#fafafa`。外侧上角 16px；中栏展开时中栏承担圆角，折叠时画布承担圆角，避免两个相邻圆角形成缝隙。
- 图标 16px、1.5px 描边、32px 点击区、6px 圆角。中栏行圆角 7px，选中底色 `#dce9f2`，左侧 3px `#3988ad` 指示条。图标栏选中仍为灰色 `#c6c6c6`，不能共用一个 selected 颜色。
- 中栏搜索高 32px、字号 12px、圆角 7px；搜索区 padding 8px。页面工作区搜索高 44px、最大宽 720px、圆角 10px，不能用无限增长的 flex 把它拉满整个宽屏。
- UI 使用系统无衬线；导航/标题 13px，说明 11px。双行列表标题 600 字重，普通导航不加粗。正文保留本地 LXGW WenKai，默认 20px/1.6，并继续尊重编辑器排版设置。
- Mac 的通用输入框归一化使用低优先级 `:where()`，局部搜索框拥有自己的圆角、底色和 focus；不要用高优先级通用规则盖掉功能设计。

中栏搜索仅过滤当前读取器已加载的展示数据，不改路由、任务状态或持久内容，不触发离开保护。切换功能上下文后清空搜索，同一作品切章节时保留查询。书架/导演/作品的固定导航入口不随内容搜索消失；搜索不是全库检索，仍受现有列表读取数量限制。资料模块仍由业务页面展示资源条目，中栏只搜索同类功能入口。

### 业务页面与弹层适配

共享业务能力不意味着共享 Web 的空间分配。Mac 的 `theme/surfaces.css` 维护控件、普通分区、设置及资产库呈现；章节和创作中枢的布局分别归 `features/editor/`、`features/creative/` 所有。不得把这些覆盖写回 Web 样式或业务后端。

- 工作台已有目录时，外层目录默认折叠但可展开；章节、书内导演台和创作中枢分别保存折叠偏好，不串到导演记录列表。设置页直接复用 Mac 分类中栏，避免两套同义导航同时占宽。
- 分栏以实际可用画布宽度决定，而非仅看窗口宽度。创作中枢用剩余高度安排会话、输入区和资料区，资料独立滚动；不能用整窗 `vh` 再叠加工具栏和说明，使输入区落到屏幕外。
- 章节编辑器是 Plate。段落及编号对齐应检查 `data-slate-node="element"`，不能只为 TipTap 的 `p` 添加样式。正文、查找高亮和段落标记共享宽度、字体与段距；保持标准、宽正文、沉浸和手动收栏的布局含义。窄画布下正文列必须排在侧栏之前，避免 AI 面板把正文挤到只能看见一行。
- 窄窗口抽屉关闭后必须同时 `visibility: hidden` 与 `pointer-events: none`，不能只靠 `translateX` 位移；否则关闭按钮会在窗口左缘留下一条可点残影。
- 导演内的正文编辑器挂在 portal 中，不能只匹配 `.mac-canvas`。全屏编辑层需独立处理高度和留白，普通弹窗的内边距、最大高度不应覆盖它。默认正文采用文楷；尊重用户显式选择的字号、行距和阅读字体。
- 图标按钮必须同时检查点击区、内边距及 SVG 的收缩；28px 业务工具按钮不应继承文字按钮左右各 11px 的内边距。
- 资产库和导演跟进使用独立分区组件，不一定有 `data-ui="card"`。按其语义结构处理浅底、分隔和选中状态；保留表单、焦点、警告、错误及拖放的边界，避免一律去掉所有 border。

原生窗口在后台可能暂停视觉动画，目录收展不依赖网格宽度或透明度动画完成；隐藏状态仍须同时移除点击与键盘焦点入口。实机复核需区分页面级路由和 portal 编辑器，不能仅以书架截图推断业务页面已适配。

## 生命周期安全边界

启动先验证依赖、配置和新构建，再请求旧窗口退出。单仓库只有一个活动桌面模式；requestedMode 和 runningMode 分开记录，失败后可重试目标模式。辅助进程由当前图形会话 launchd 托管，终端退出不影响窗口。稳定 PID 的 supervisor 负责日志轮转及 SSH 有界退避重连；其他角色失败不无限重启。

服务器模式在生命周期锁内检查 Mac、client 和 shared 工作区的直接依赖及本机 Vite 命令。Git 切换分支会保留 `node_modules`，同名包也可能对应另一组锁定版本，因此启动记录同时校验当前锁文件、安装配置、工作区清单和 pnpm 的实际安装快照。

发现缺项或记录失效时，仅对 Mac 桌面和它引用的工作区执行冻结安装。运行依赖与构建依赖都要纳入，否则生产环境变量可能使 Vite 缺失。安装后复查链接再记录成功，中断或失败会在下次启动重试。服务器模式重启在请求旧窗口退出前完成同一检查。

前端和 Swift 各有独立的构建指纹。前端覆盖 Mac 页面、复用的 client/shared、Tailwind 配置、锁文件、安装快照和 Vite 构建环境。原生窗口覆盖 Swift 源码、资源、构建脚本、应用版本、编译器及 SDK。开发模式使用 Vite 提供实时页面，只查原生窗口缓存。

每次构建先写私有临时目录，核对必需文件、产物内容摘要、可执行权限以及构建前后的输入。原生构建还需验证签名。成功后以原子替换发布缓存索引，窗口及回滚状态始终保存实际的版本目录。遇到缺失资源、摘要失配、旧格式或中断的构建时生成独立目录，避免覆盖仍在使用的页面或签名包。

排查启动慢时，在 `.logs/desktop_mac/lifecycle.log` 按命令名和 PID 查看本次构建、窗口确认、服务注销、连接和页面就绪耗时。总耗时包含各子阶段，回滚也经过相同的计时入口。日志仅记录阶段、结果及耗时，作品内容和连接凭据留在各自的数据边界内。

本机服务直接运行原 ts-node-dev 入口，不能调用会隐式 `prisma db push` 的 `server dev`。Node 选择只加载 Prisma 导出并打开内存 SQLite 验证 ABI，不导入后端 bootstrap。启动时将已校验的数据库绝对路径传入服务，避免继承环境变量改变数据源。

新窗口启动后如果健康检查失败，必须先走同一个正常关闭协议；取消或超时则保留整套进程及身份记录，不能拆掉窗口依赖或再打开回滚窗口。重启及回滚全过程持有同一生命周期锁。

### 启动身份与就绪顺序

- 后台 WKWebView 可能暂停绘制帧。收到原生退出请求时直接读取注册文档的修改和忙碌状态；需要用户处理时，带当前请求 ID 通知原生窗口前置。保存完成后在 React 提交后复核文档状态。超时只取消对应请求，迟到的答复不能关闭下一次请求的窗口。
- `launchctl bootout` 的成功回执只表示系统接受退出。进程归属校验通过后发出退出请求，轮询同一图形会话的服务名，直至 `launchctl print` 明确报告服务不存在。启动和回滚在注册同名代理前也要确认该条件，权限错误和等待超时需上报。
- 开发界面由 supervisor 在 `desktop_mac` 工作目录直接启动工作区的 `.bin/vite`。该入口通过 `exec` 运行 Vite，退出信号可以直接送达 HTTP 服务。`pnpm exec` 作为中间进程时，开发服务可能一直占用端口，直到 launchd 的退出宽限期结束。
- 确认旧窗口进程退出后，先清除磁盘状态中的窗口记录，再注销辅助服务。保留服务归属和上次成功的构建路径。即便注销被打断，下一次命令也能重新核对服务或恢复旧构建。
- SSH 的命令行目的地址可能是用户配置的别名。借用已有隧道时读取进程真实 argv（只取 argc 项，不输出环境变量），验证其 `/usr/bin/ssh` 可执行文件、精确 `-L` 转发，并用 `ssh -G` 对比主机、用户、端口与连接身份配置。不能用 `command.includes(host)` 证明或否定目标身份。未知选项/不支持的代理命令按归属不明处理，不能停止该进程。
- `launchctl print` 返回 PID 时，该 PID 可能仍在执行 `xpcproxy`。必须等真实 argv 等于本次提交的 ProgramArguments，才能记录完整命令与启动时间；后续停止仍严格检查身份，不放宽为只看 PID。
- helper 进程存活不等于页面已能加载。先等待界面 HTTP 健康和 API 转发，再创建 WKWebView；尤其 Vite 冷启动不能和原生首次导航竞速。恢复旧构建也遵守同一顺序。
- native 的 focus 回复需要带回与 status 相同的 repo/mode/backendIdentity，供重复启动核对身份；只返回 `ok` 不足以证明聚焦了目标窗口。

发停止信号前核对仓库、角色、模式、PID启动时间和完整命令/launchd归属，避免PID复用。borrowed API/隧道永不停止。owned本机API须完成只读持久任务/租约/重试检查，覆盖不足就保留，关窗口不等于取消作品生产。

### 记录失效、孤儿 agent 与陈旧锁

- 状态记录的 PID 被系统复用后，记录与进程不再匹配。此时改为检查该角色的仓库专属 launchd label：label 未加载即视为已停止；label 仍在运行本仓库 `supervisor.mjs` 且 argv 角色一致时，按 label 卸载；运行其他程序时以退出码 4 拒绝，不发送信号。
- 启动保存新状态后、停止保存剩余状态后，都会清理未被状态记录引用、但仍由本仓库 supervisor 运行的 mac-proxy/vite/native-watcher label。这样上一次失败留下的 15175 代理不会长期占端口。
- `ts-node-dev --respawn` 改代码后会换出新的 API 子进程。端口监听者若是本仓库 `local-api` label 的后代，应重新登记为 owned（记录 supervisor PID），不能降级为 borrowed；否则 `stop_app` 永远不会关闭自己启动的服务。
- 生命周期锁记录 `machineId`（IOPlatformUUID）。macOS 的 `os.hostname()` 会随网络变成 `bogon` 等值，不能用来判断“同一台机器”。仅当锁来自本机、同一仓库且持有 PID 已不存在时自动回收（先原子 rename 再删除）；PID 仍存活、锁不可读、来自其他机器或旧版锁缺少 machineId 时保持拒绝，由人工确认后处理。
- 锁冲突与归属无法确认是两类失败：`make` 输出需分别提示“另一个启动或关闭命令正在运行”与“无法确认进程归属”，不能共用退出码 4 的同一句提示。

## 部署与回滚

`make server_update` 从本地发布分支部署，`DEPLOY_REF=origin/ai` 要求开发机和服务器检出同一 fork 的 `ai` 分支。候选是本地已提交的 HEAD，服务器通过 SSH 接收缺少的 Git 对象。版本变更须能从服务器基线快进。版本变更时，候选构建和回归的执行或复用依据写入绑定 SHA 与分支的验证记录。已提供同一提交的有效记录时可复用测试结果。版本相同也会重启并检查两个服务。涉及数据库 schema、迁移、启动兼容层或数据库依赖变化时，按独立的数据库升级流程处理。

锁顺序：本机生命周期→本机部署→远端deploy.lock→远端service-control.lock。持有服务锁时直接调用经过WorkingDirectory归属校验的systemd服务，不嵌套调用会再次加锁的control.sh。

部署清单保存 Git SHA、Linux 工具链以及七个依赖和构建目录的 SHA-256。校验同时涵盖文件内容、权限、归属和符号链接目标。旧清单首次升级时完整构建。已有基线的线上文件发生漂移时在停服前报错，保留现场。提交和校验值一致时只重启并验证两个服务，保留部署清单中的上一版和备份路径。

普通前端或后端变更只替换对应的 dist。Web 构建还读取 `desktop/package.json` 中的版本。共享包采用 pnpm 注入，变更后需要更新依赖中的副本及其消费者。锁文件、全局构建输入或未知路径采用完整构建。增量构建和回归使用候选源码及私有依赖副本，保持线上目录独立。`validation.json` 区分本次执行和基于同一组输入复用的检查。

版本切换的预备份与静止备份都使用 SQLite backup API 和完整性校验，保存资产和配置。预备份还包含旧源码、Git bundle 及 `release.json`。该文件把旧 SHA 的每个产物目录映射到 `artifact-store/<目录>/<SHA-256>`。校验后独立保存的目录可跨发布复用，人工恢复时须复制回清单所列的原相对位置，以保留 pnpm 的相对链接。即时回滚只移回事务实际更换的目录。每批的 `timings.json` 保存阶段秒数，`candidate-total` 包含其构建子步骤。

维护期正常18080的API请求503，保留精确health与静态页；18081仅服务器回环GET/HEAD探测。两次空闲检查相隔 5 秒。已有 API 连接可以自然排空约 30 秒，持久队列、租约、重试和未知状态继续阻止停服。若此次在切换前中止，重试时可复用同一提交已验证的候选，须匹配线上基线、完整产物校验值、运行工具链和构建范围。数据快照按本次切换时间重新生成。后台仅内存执行、又没有持久记录的工作仍依靠连接检查，因此不能承诺零中断热更新。

新版本先在临时检出的候选提交上启动。Nginx 重载是异步的，维护探测端口通过后，正式入口仍可能短暂返回 503。正式入口在 30 秒内重试首页、健康接口和小说列表读取。两处入口均通过后才以快进方式更新并检出发布分支，同时校验分支仍指向预演时的提交。

切换失败时，按事务记录恢复旧源码、依赖、产物、Nginx 配置及服务状态，数据库保留现场数据。若发布分支仍指向旧版，回滚会重新检出该分支。遇到旧部署曾把分支提前推进的回滚，允许从干净的 detached HEAD 重试的条件是：部署清单与工作区的旧提交和发布分支一致，最近一次切换的事务记录为 `rolled_back`，且候选能同时从线上旧提交和已记录的分支头快进。

### 异常中断的人工恢复

1. 阅读该批次transaction.json与backups/*/manifest.json，核对文件大小及SHA256，确认两个服务的归属和当前状态。不要删除锁/回滚槽来跳过检查。
2. 若phase未complete/rolled_back/aborted，先检查实际目录和pending操作：root为当前槽、candidate为新产物槽、rollback为旧产物槽。rename是原子操作；事务记录在每次rename之前和之后写入。
3. 保持API维护入口，确认没有活跃任务及连接后停既有服务。将已安装的新产物移回candidate；将rollback中旧目录逐项移回原位。不能删除有来源不明内容的目录。
4. 源码无未提交修改时非强制切到记录的old SHA；不操作数据库。恢复preflight配置归档中的原Nginx，先nginx -t，再启动原先运行的服务并检查API、网页、小说读取。
5. 确认维护探测端口消失，记录人工恢复结果。核对发布分支再进行下一次部署。未知情况保持现场，不自动重试切换。
