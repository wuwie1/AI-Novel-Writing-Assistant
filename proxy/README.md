# 本机模型代理

在运行 SSH 通道的电脑上提供 OpenAI 兼容 API 中转。服务器经反向通道访问本机，由本机访问 `config.toml` 的 `openai.url`。此目录不属于服务端运行依赖，无需在服务器安装、配置或启动代理。

## 使用

依赖 Node.js（沿用项目要求）、Python 3.11+（标准库解析 TOML）、autossh、lsof，以及本机到服务器的免交互 SSH 登录。服务器沿用仓库的 Linux/systemd 部署，需允许远程 TCP 转发，保留 `GatewayPorts no`；健康检查使用服务器的 `curl` 和 `ss`。

首次使用把 `config.example.toml` 复制为 `config.toml`，填写实际 API 根地址：

```toml
[openai]
url = "https://api.openai.com/v1"
```

配置文件仅保存在本机，被 Git 忽略。程序不会覆盖已有配置，不在此文件存放密钥；页面中的厂商 API Key 会随请求转发。

在仓库根目录运行：

```bash
make ssh_server          # 启动/复用代理与 Web、Qdrant、模型反向通道
make ssh_restart_server  # 重启这些本机服务；修改配置后使用
make ssh_stop_server     # 关闭这些本机服务；远端 API、网页和数据库继续运行
```

沿用 `SSH_TARGET` 或桌面配置中的服务器。启动成功后，在「模型与厂商 → 配置连接」选择「使用本机代理」，保存并测试连接。模型名、密钥和鉴权方式须与 `openai.url` 对应的服务一致。所有选择代理的厂商共用这一个上游地址，不按模型名或厂商名分流。

固定路径为：服务器 `127.0.0.1:14000` → SSH → 本机 `127.0.0.1:14000`。页面保存 `http://127.0.0.1:14000/v1`，两端端口是固定契约。未选择的厂商继续使用原地址。电脑需保持在线；代理停止不会自动切回服务器直连。`make ssh_server` 不自动恢复业务任务。

## 模块职责

- `server.mjs`：回环监听、健康接口和进程退出。单独运行可用 `node proxy/server.mjs`，不会创建 SSH 通道。
- `infrastructure/config.mjs`：读取 TOML、验证固定上游，不输出配置正文。
- `infrastructure/forward.mjs`：透明转发 `/v1/` 请求，保留状态码、鉴权、查询参数和响应字节；请求及响应均使用流与背压。代理不做协议转换、模型选择、重试或结果修复，不跟随上游重定向。
- `application/lifecycle.mjs`：在现有仓库生命周期锁内管理自有进程。只保存 PID、进程归属、配置指纹等控制信息，验证完整进程参数和健康身份后复用/停止；不会按端口批量杀进程。autossh 负责隧道断线重连，代理意外退出可重新运行启动命令。
- `index.mjs`：外部生命周期入口。服务器业务不导入这个模块。

代理不写访问日志、错误日志、请求体、响应体或密钥，不积累模型内容，不添加磁盘缓存；连接错误只返回通用 502。`.runtime/local-proxy/` 的进程信息和 SSH 配置只用于管理通道，不含模型请求。服务端原有用量统计和应用日志不属于代理，不由此功能关闭。

本机健康检查不请求真实模型；服务端通过隧道回读相同实例身份，并检查监听仅绑定回环地址。启动失败回收本次新建的代理/通道，保留已有服务。某一通道失败不阻止其他通道的停止操作。

## 验证

```bash
node --experimental-strip-types --test proxy/tests/*.test.mjs
```

转发测试使用临时本机模拟上游，不调用付费模型。覆盖 SSE 首段即时转发、图片表单字节、鉴权、错误与重定向、断开取消、配置校验、进程归属、幂等启动、停止/重启和失败回收。
